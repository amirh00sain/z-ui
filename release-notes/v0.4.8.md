# xray-pilot v0.4.8

HTTP / SOCKS5 proxy protocols: a node can expose a plaintext proxy port for runtime programs (IP allowlist plus optional auth), completely separate from the subscription system. Verified end-to-end on a real node.

## Added

### HTTP / SOCKS5 proxy protocols

Built for the "give a program a proxy" case: create an HTTP or SOCKS5 template on the profiles page, bind it to whichever nodes need it, and point the program at `http://node-ip:18080` or the SOCKS5 port.

- **IP allowlist** (`allowed_ips`): single IPs and CIDR ranges side by side, implemented with xray routing `source` rules — allowlisted sources go direct, everything else on that inbound goes to blackhole
- **Optional authentication** (`accounts`): `[{"user":"...","pass":"..."}]` enables username/password auth (SOCKS5 automatically switches to `auth: password`). Auth and the allowlist are an "or"
- **Private-target switch** (`allow_private`, default false): controls whether allowlisted sources can reach internal targets through the proxy. Blocked by default — cloud metadata and the node's own services are unreachable — and when enabled the inbound's allow rule is placed before the `geoip:private` block. Node-level overrides are supported (an explicit `false` overrides a template `true`)
- **Node-level overrides**: allowlist, accounts, the private switch and the port can all be overridden per node

### Safety guards

- The inbound is **refused when neither an allowlist nor auth is configured**, which stops an accidentally public open proxy from being scanned and abused
- Invalid allowlist entries (not an IP or CIDR) also refuse generation, so xray never fails to start. Both problems surface as warnings in the sync preview and do not affect other protocols
- **Subscription isolation**: http / socks never appear in subscription URIs, Clash, sing-box output or the subscription page — locked in by test cases — and a node bound only to a proxy protocol is hidden from subscriptions automatically

### Experience

- HTTP / SOCKS5 appear in the protocol dropdown, which fills in an allowlist template and a default port (18080 / 11080) when you switch
- The profile name defaults to the protocol type, and switching protocols later no longer overwrites a name you edited

## Notes

- Proxy accounts are unrelated to the user system, so the instant-apply gRPC path automatically skips proxy inbounds
- SOCKS5 currently proxies TCP only (`udp: false`)
- For a public deployment, consider an extra source restriction on the proxy port in your cloud security group as a second layer
