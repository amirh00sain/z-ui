# xray-pilot v0.4.7

Node list usability plus production fixes: server-side filtering, health visualisation, a changelog entry point, and fixes for bulk-delete lock conflicts and subscription breakage caused by stray spaces in addresses.

## Added

### Server-side node list filtering

- Keyword, sync status, region and owner filters all run on the server, **across every page** (previously only the current page was filtered)
- Region and owner dropdown options now come from the full dataset via a new `GET /api/nodes/filter-options`, so they no longer break as you page
- The search box debounces at 300ms and a filter change returns you to page 1

### Node health visualisation

- A health dot in front of the node name, with the same semantics as the dashboard: green = check passed, red = check failed, grey = never checked. Hover for latency and the last check time
- Unhealthy nodes get a red "health check failed" note under the region row
- A new health filter (healthy / failed / not checked) so you can show only the nodes that need fixing

### Quick copy for connection addresses

- The IP and domain in the connection column each have their own copy button, with a toast confirming the copy

### Changelog

- "Changelog" in the avatar menu, and the version number in the bottom-left of the sidebar opens it too
- The changelog drawer shows versions on the left and content on the right, with click-to-jump and a highlight that follows the scroll
- release-notes are embedded into the binary at build time (new `GET /api/system/release-notes`), so the content always matches the running version
- The version on the login page links to GitHub Releases

### Duplicate subscription node check

- A new "duplicate subscription node" diagnostic: it finds subscription nodes that are identical apart from their name. Clients such as V2rayN and Shadowrocket silently de-duplicate those on update, which shows up as "the subscription page has N nodes but the client only has N-1"

## Fixed

- **Bulk node deletion failing with "database is locked (5) (SQLITE_BUSY)"**: the SQLite connection pool is now a single serialised writer with a busy_timeout backstop, and the UI deletes serially, reporting success and failure per node
- **Leading or trailing spaces in a node IP or domain breaking subscription URLs** (a value such as `" tw03.xxx"` is dropped by clients): the UI and the service layer both trim every text field. Re-saving an affected node corrects existing data and correctly triggers a resync plus known_hosts cleanup

## Changed

- Go updated to 1.26.6 with a full dependency refresh (gRPC v1.83.1, GORM v1.31.2, modernc.org/sqlite v1.57.0, golang.org/x/crypto v0.55.0 and others)
