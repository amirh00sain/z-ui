# xray-pilot v0.4.2

Closing the loop on one-click provisioning: firewall guidance plus an SSH connectivity check after registration.

## Added

### Automatic panel outbound IP detection

- Every hour the backend fetches the panel's outbound IP through an external probe (https://api.ipify.org by default, overridable with `XRAY_PILOT_OUTBOUND_PROBE_URL`) and writes it into the system settings
- The settings page gained a "Panel outbound IP" module showing the detected value, with a manual override for multi-IP, NAT and container setups
- After generating a command, the provisioning dialog states clearly: make sure the node firewall allows the panel IP `X.X.X.X` over SSH

### SSH connectivity check after registration

As soon as the bootstrap script registers back with the panel, the panel probes the node's SSH port:

- **Reachable**: the success state shows a green "✅ The panel can reach the node over SSH (latency X ms)" and closes after 3 seconds
- **Not reachable**: it shows an amber "⚠️ The panel cannot reach the node over SSH yet" plus the specific error (including the panel outbound IP), pointing you at the firewall before a manual sync; this one stays open for 7 seconds

This closes the last gap in v0.4.0 provisioning — "the script succeeded" no longer has to mean "the panel can SSH into the node". You now learn the answer while still at the machine.

## Upgrade

- The database schema migrates automatically (`node_install_tokens` gains the reachable fields; two new system setting keys). No manual steps
- No breaking API changes — overwrite the binary and restart

## Notes

- Behind a container or reverse proxy the automatic probe may return the ingress IP — set it manually under Settings → Panel outbound IP
- The SSH check times out after 5 seconds and uses the node's configured port when it is not 22
