# xray-pilot v0.4.5

User changes now apply immediately over the xray gRPC API, **without restarting xray** — removing the "change one user → restart every node → drop every live connection" bounce.

## Added

### Instant apply over gRPC (no restart on user changes)

Previously every create / delete / enable / disable, group change or UUID reset marked the affected nodes as pending sync, pushed a full config over SSH and ran `systemctl restart xray`. The restart dropped **every** live connection on that node.

This release wires up xray's gRPC `HandlerService.AlterInbound` to add and remove users on a running xray:

- **Instant**: the panel reaches the node-local xray gRPC API (127.0.0.1:10085) over an SSH tunnel and calls AddUser / RemoveUser in milliseconds — no restart, no impact on other users
- **Double write for durability**: the latest `config.json` is also written to the node (**without restarting**), so user state survives an xray restart
- **Safe fallback**: if SSH, the config upload or the gRPC call fails on any node, that node falls back to the existing "mark drift + restart sync" path, so no operation is ever lost

Covered user operations: **create / delete / enable / disable / change groups / reset UUID**. Group changes are reconciled as a set difference between the old and new node sets, so only genuinely affected nodes are touched.

### Toggle and how to enable

- New system setting **"Instant apply via gRPC (no restart when users change)"** under Settings → Xray runtime
- **Off by default**: with it off, behaviour is identical to v0.4.4 (mark drift + restart sync)
- Turn it on to drop the restarts; try it on a test node before enabling it everywhere

## Deliberate boundaries

- **Drift detection is unchanged**: it still reads the remote `config.json` over SSH and compares. gRPC was not used there because StatsService cannot see idle registered users and the reconciliation would under-report
- **No gRPC add/remove for nodes or profiles**: adding a profile or a node still goes through a full SSH sync (including the restart)
- **Hysteria2 is skipped**: it is not part of xray-core, so gRPC cannot manage it and those inbounds are ignored
- **Changing a username (email)**: that is a cross-node email change, so it falls back to a full restart sync (a rare operation)

## Upgrade

- No breaking changes; the new setting defaults to off, so behaviour matches v0.4.4 until you enable it
- No schema changes
- Prerequisite: the node's xray config must include the API inbound (127.0.0.1:10085). That inbound has been part of the generated config since v0.2.x (traffic accounting already used it), so any properly synced node satisfies it

## Also

- New `cmd/grpcsmoke` operations smoke-test tool: independent of the panel, it connects straight to a node with explicit SSH parameters to verify gRPC user add/remove (`go run ./cmd/grpcsmoke -h` for usage)
