# xray-pilot v0.4.6

Replace a node's server in one click: when a VPS dies or you move IP, **keep every group link, protocol key and node-level override**, so client subscriptions never change.

## Added

### Replace server (node list → row menu → "Replace server")

When a node's VPS failed or was migrated, the only option used to be deleting the node and provisioning a new one — losing the group links, the Reality private key and every port / SNI override, and breaking the node in every client subscription. This release offers two one-click paths.

**IP change only** (same server, for example after moving an elastic IP):

- Enter the new IP and save; the node automatically becomes pending sync
- The old IP's known_hosts entry is cleaned up automatically
- If the node has a domain configured, you are prompted to update DNS manually

**Replace server (re-provision)** (a brand-new machine):

- Reuses the v0.4.0 one-click flow: generate a one-time token and curl command, run it on the new machine
- The script installs xray, writes the panel public key and registers back with the panel
- Registration **updates the existing node** (IP / SSH / xray version) instead of creating a new record — the node ID stays the same, and groups, protocol keys (Reality private keys) and port / SNI overrides are preserved
- When the new machine is reachable over SSH, a **config sync is triggered automatically** so the node is back in service as fast as possible
- Domain-connected nodes are invisible to clients once DNS has propagated; IP-direct nodes just need a subscription refresh

Both paths guarantee **the same subscription URL and the same node keys**.

## Improvements

- The "Copy command" button in the provisioning / replace-server dialog is now a solid primary button, which reads better against the dark code box

## Security

- Replace-mode tokens inherit all the provisioning constraints: single-use, 10-minute TTL by default, bound to the first IP that uses them
- Registration consumes the token before updating the node, so concurrent duplicate registrations succeed only once

## Upgrade

- No breaking changes; `node_install_tokens` gains a `replace_node_id` column (handled automatically by AutoMigrate, existing data untouched)
- `node-bootstrap.sh` needs no update — both modes share the same script
