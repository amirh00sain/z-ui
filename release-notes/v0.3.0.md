# xray-pilot v0.3.0

Multi-protocol coexistence plus two-way node↔profile editing.

## Added

### Several protocols on one node, safely

A single node can be bound to multiple protocols at once — VLESS+Reality, Trojan, VLESS+WS+TLS and so on — without conflicts. Each protocol can override its own listen port (for example Reality on 443 and Trojan on the same node moved to 8443); the backend validates port uniqueness per TCP / UDP and rejects conflicts with an explicit error. All three subscription formats (URI, Clash, sing-box) follow the node port, so the client connects to what the node is actually listening on.

### Profile axis: configure one profile across many nodes

The "Configure node keys" drawer is now a two-column layout. Select nodes on the left → generate keys and save in bulk on the right. For a 12-node all-Reality setup that is three steps (select all → bulk generate → bulk save), and every node still gets its own key.

### Node axis: bind many profiles to one node

Clicking a profile badge in the node list opens the new "Node profiles" drawer. Select profiles on the left → bind in bulk on the right, so a brand-new node gets every protocol attached in one pass. Port conflicts are flagged live while editing and block the save.

### Node owner field

Nodes gained an "Owner" field to record where they came from (provider codename, team name and so on). The node list shows an owner column and a filter dropdown, and search covers the field.

## About Hysteria2

Hysteria2 is a separate project from Xray — the xray-core kernel does not speak the protocol. In this release:

- Subscription output (URI / Clash / sing-box) **fully supports** Hysteria2, and the port-conflict guard correctly treats it as UDP so it can share port 443 with Reality
- The Xray config generator deliberately does **not** create an inbound for Hysteria2, which would stop the node's xray from starting

Managing a real Hysteria2 server (its own `hysteria` binary deployment pipeline) will be evaluated as a separate feature in a later release.

## Upgrade

- The database schema migrates automatically (new `node_profile_keys.port` column) with no impact on existing data
- No breaking API changes
