# xray-pilot v0.5.0

Multi-admin accounts: admins stored in the database, two roles, in-panel create / edit / delete and password changes. The activity log now records the actor on every entry and can filter by source.

## Added

### Multiple admin accounts

- Admin accounts now live in the database; create, enable / disable, reset passwords and delete them under Settings → Admins
- Two roles: **super admin** can manage accounts; **admin** has every operational permission but can only change their own password
- The avatar menu shows who you are, and gained "Change password" (current password required)
- Failed sign-ins are written to the activity log (wrong password / disabled account)
- Safety guards: at least one enabled super admin must remain; you cannot delete, disable, change the role of, or reset the password of your own account (use "Change password" in the avatar menu); disabling or deleting an account invalidates its live sessions immediately

### Activity log sources

- Every entry records the actor: an admin username, a background scheduler task, the node provisioning script or a Feishu callback
- The log page gained a "Source" column with one-click filters for admin actions, background scheduler, node provisioning and Feishu callbacks

## Fixed

- **Database backup downloads timing out**: large backups (tens of MB) failed through a CDN or reverse proxy because the frontend's 10-second request timeout aborted the transfer. Download requests no longer carry a timeout

## Changed

### Theme

- Primary colour moved from green to blue; dark mode went from pure black to three neutral zinc steps (sidebar and header darkest, content next, cards lightest) with heavy shadows removed; light mode became a cool grey canvas with white cards
- The sidebar marks the current page with a solid blue pill in light mode and a neutral light pill in dark mode; colour is reserved for buttons and status
- Success / warning / danger colours now come from theme variables, calibrated per mode; secondary text and warning / success text in light mode were re-derived against WCAG AA
- The header no longer matches the cards: it shares the page background in light mode and the sidebar colour in dark mode, tying the frame together
- Inter and IBM Plex Mono are now self-hosted with the binary instead of loading from Google Fonts (no first-paint stall on restricted networks), with a Chinese fallback added to the stack
- Remaining emoji icons (lock, warning) were replaced with linear icons for a consistent look across platforms

### Consistent page layout

- Every page opens with a toolbar (search / filters / primary action); the in-page description that duplicated the header is gone
- Removed several "card inside a card" patterns: list tables are no longer wrapped in another card, and the side explanations and settings lists use divided groups instead
- Alignment fixes: dashboard "Recent activity / Node health" share the column grid with the traffic cards above and have equal header heights; the log page's source filter moved to the first row and the table lines up with the explanation card

### Dashboard and alerts

- "Overview" was renamed "Dashboard"; metric card sublabels no longer use green and only turn red when something is wrong
- The "nodes pending sync" notice moved from a content banner to a status pill in the header, expanding into details and "Sync all"; the sidebar Nodes item also shows a pending count badge. The content area is no longer pushed around

### Settings page reworked

- The single long-scrolling page became five sections in the sidebar's Settings submenu: Status, Nodes and sync, Subscription and notifications, Backups, Admins. Each has its own URL (for example `/settings/backup`) so a refresh stays on the current section
- Form-based sections share a bottom save bar showing pending changes with revert; read-only diagnostics and the admin list no longer show a save button
- The auto backup interval moved into Backups, next to the backup directory and retention
- Switching sections with unsaved changes asks for confirmation first
- The "Keys / lock" button on the profiles page now matches the neutral styling of "Edit"

## Upgrade

- New `admin_users` table, migrated automatically. On **first start** the `admins` section of `config.yaml` is written into the database, with the first account as super admin; after that the section is ignored and accounts are managed in the panel
- **All existing sessions end after upgrading and you must sign in once more** (the new token carries the account ID)
- No change to the `users` table; the "Source" column is empty for log entries from before v0.5.0
